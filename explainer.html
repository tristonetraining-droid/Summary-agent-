System Explainer

CIM Summarizer
How It Works

Upload a 100-page investment document. Get a clean, AI-generated summary you can edit and export — in minutes.

End-to-End Flow

The Complete Journey

📄
Step 1 — Frontend

User Uploads PDF

The user visits the home page, enters a Deal Name and Sponsor Name, then drags and drops a CIM PDF file. They click Analyse.

⚙️
Step 2 — Backend

Backend Creates a Job

The file is sent to POST /api/jobs. The backend saves the PDF to disk, creates a Job object with a unique ID (like a ticket number), and puts it in a queue. It immediately returns the Job ID to the frontend.

📡
Step 3 — Frontend

Progress Page Opens + SSE Begins

The frontend navigates to /jobs/{id} and opens a live Server-Sent Events stream. Like a radio broadcast — the backend keeps sending stage updates and the frontend listens in real time, animating each pipeline step.

🤖
Step 4 — AI Pipeline

5-Stage AI Pipeline Runs

The backend processes the PDF through 5 stages: Ingest → Classify → Extract → Synthesize → Assemble. Each stage emits progress events that stream to the browser. Detailed breakdown below ↓

✏️
Step 5 — Frontend

Edit Page — Live Preview + Editors

Pipeline completes → browser auto-navigates to /jobs/{id}/edit. Left side shows a scaled live document preview. Right side shows accordion editors for each CIM section. Every keystroke autosaves after 800ms.

💾
Step 6 — Database

Save to History (Supabase)

User clicks "Save to History". The full summary JSON is sent to Supabase (cloud database) with a timestamp. It can be retrieved later from the History drawer by clicking any saved deal.

📥
Step 7 — Export

Export PDF or DOCX

Clicking Export PDF or DOCX sends the latest summary to the backend. It builds a formatted Word document using python-docx, then converts to PDF via LibreOffice headless. The file downloads instantly.

AI Pipeline

5 Stages Inside the Backend

Stage 1
📄

Ingest

Reads every page of the PDF and extracts raw text. Handles multi-column layouts, tables, and encoded fonts.

pdfplumber
Stage 2
🗂️

Classify

Sends page text to GPT and asks: "Which CIM section does this page belong to?" — Deal Overview, Sources & Uses, Investment Highlights, etc.

GPT-4o
Stage 3
⚡

Extract

Fires 11 AI calls in parallel — one per CIM section. Each call extracts structured data: tables, criteria checkboxes, bullet points, financial figures.

GPT-4o · ThreadPoolExecutor
Stage 4
✨

Synthesize

One final AI pass that reviews all sections together — fixes inconsistencies, aligns tone, and ensures numbers are consistent across sections.

GPT-4o
Stage 5
📋

Assemble

Converts the structured JSON summary into a polished, formatted .docx Word document with proper headers, tables, and checkboxes.

python-docx
Real-Time Updates

How Live Progress Works (SSE)

⚙️

Backend (Python)

Pipeline runs in a background thread. After each stage it pushes an event into an asyncio Queue — like dropping a letter in a mailbox.

→
SSE Stream
→
🖥️

Frontend (React)

An EventSource connection reads from the queue. Each event updates the progress bar, the spinning stage indicator, and the live message — instantly.

Components

Every Piece of the System

📄
Frontend · Page

Upload Page /

The entry point. User fills in deal info and drops a PDF. On submit it calls POST /api/jobs and navigates to the progress page.

Key detail: The file is sent as multipart/form-data. The backend responds immediately with a job ID — the heavy AI work happens async in a background thread.
📡
Frontend · Page

Progress Page /jobs/[id]

Animated checklist of pipeline stages. Connects to the SSE stream and updates in real time as the AI processes each stage.

Key detail: Uses a "trickle" animation — even between real events the progress bar slowly creeps forward so it never looks frozen. queued state maps to step 1 so the spinner shows immediately.
✏️
Frontend · Page

Edit Page /jobs/[id]/edit

Side-by-side layout: live preview on the left, editable accordion fields on the right. Every change autosaves after 800ms.

Key detail: Preview uses transform: scale() computed at runtime via ResizeObserver so the A4 document always fills its column exactly regardless of screen size.
🗒️
Frontend · Component

DealSummaryPreview

Renders the CIMSummary data object as formatted HTML that mirrors the final exported document — tables, checkboxes, styled headers.

Key detail: What you see in the preview = exactly what gets exported. The same JSON object drives both the preview HTML and the python-docx assembly.
🎛️
Frontend · Component

SectionEditors

One collapsible accordion panel per CIM section. Text fields, checkboxes, and tables with add/remove rows — the right input for every data type.

Key detail: Every change calls onChange(updatedSummary) which bubbles to the Edit page and simultaneously updates the live preview on the left.
📚
Frontend · Component

HistoryDrawer

Slide-in panel from the right showing all previously saved deal snapshots. Click any row to open that saved state.

Key detail: Uses a React Portal — renders directly on document.body, completely outside the page layout tree, so no CSS can accidentally hide or clip it.
🕐
Frontend · Page

History View /history/[id]

Opens a previously saved snapshot. Same layout as the Edit page but loads the CIMSummary JSON from Supabase instead of a live job.

Key detail: Export buttons still fully work — they send the loaded historical summary to the backend for fresh conversion to PDF/DOCX.
🤖
Backend · Python

pipeline_core.py

The brain of the system. Orchestrates all AI calls in order: Ingest → Classify → Extract → Synthesize → Assemble.

Key detail: Extract runs 11 GPT calls in parallel using ThreadPoolExecutor. After each stage, it calls on_progress(stage, message, pct) which pushes an event to the SSE queue.
📬
Backend · Python

jobs.py

Tracks every running job by ID. Manages the SSE event queue — the mailbox that connects the pipeline to the browser.

Key detail: An in-memory JOB_REGISTRY dict stores each Job. Each job has an asyncio.Queue. Pipeline puts events in → SSE endpoint drains them out to the browser.
📥
Backend · Python

pdf_export.py

Converts the assembled Word document to PDF using LibreOffice running headlessly (no UI) on the server.

Key detail: Calls soffice --headless --convert-to pdf via subprocess. LibreOffice converts exactly like "Save As PDF" in Word — full formatting preserved.
🗄️
Database

Supabase

Cloud Postgres database that stores saved summary snapshots. No custom SQL — uses Supabase's auto-generated REST API.

Key detail: "Save to History" sends the full CIMSummary JSON + metadata (deal name, sponsor, timestamp) via POST. The History drawer reads with GET. Simple and serverless.
